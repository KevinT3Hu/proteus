# Localization with Fluent

Proteus uses Project Fluent (`fluent-bundle` 0.16.0) for message parsing,
formatting, select expressions, terms, attributes, and CLDR plural rules.
`fluent-langneg` 0.13.1 handles language negotiation (the version compatible
with fluent-bundle's `unic-langid` API); `unic-langid` 0.9.6 validates locales.
The shared `proteus-i18n` crate is an adapter for resource ownership, locale
preferences, and fallback. It contains no custom message parser or plural rules.

English and Simplified Chinese UI resources are included. Shell output, program
titles, paths, and user/plugin text retain their original content. CLI help and
developer diagnostics currently remain English. Terminal layout does not yet
implement bidirectional text; Fluent isolation marks are disabled for cell layout.

## Language selection

```lua
local p = require("proteus")
p.config { language = "zh-CN" }
```

Without an explicit language, Proteus checks `LC_ALL`, `LC_MESSAGES`, then `LANG`,
and defaults to English. POSIX names such as `zh_CN.UTF-8` are accepted;
`C`/`POSIX` mean English. Tags are validated/canonicalized by unic-langid
(e.g. `zh-CN`). Fluent language negotiation selects matching catalogs; English
is the final fallback. Language changes apply on config reload.

## Lua API

`p.i18n.load(locale, source)` loads standard Fluent text while config loads.
It can be called from ordinary Lua modules loaded with `require`. Later resources
override earlier entries in that locale. Syntax errors and duplicate IDs within
one resource reject the entire load; a bad config reload keeps the running config.

```lua
local p = require("proteus")
p.i18n.load("en", [[
-brand = Proteus
welcome = Welcome to { -brand }, { $name }!
files = { $count ->
    [one] { $count } file
   *[other] { $count } files
}
]])
p.i18n.load("zh", [[
welcome = 欢迎使用 Proteus，{ $name }！
files = { $count } 个文件
]])
p.keymap("normal", "alt+h", function()
  p.notify(p.i18n.t("welcome", { name = "Lua" }))
end)
```

`p.i18n.locale()` returns the effective configured tag. `p.i18n.t(id, args)` formats
a Fluent message or `message.attribute`. Lua numbers remain numbers for Fluent
plural selection, including decimals; strings remain strings. Booleans become
`"true"`/`"false"` strings. Missing messages, missing arguments, and Fluent
resolution errors raise Lua errors. Argument text is never parsed as Fluent.

To load a separate file, read its contents and pass them to `p.i18n.load`.
To customize base UI text, use its native Fluent ID:

```lua
require("proteus").i18n.load("en", [[
ui-split-right = Split horizontally
]])
```

Base resources are [`en.ftl`](../crates/proteus/src/locales/en.ftl) and
[`zh.ftl`](../crates/proteus/src/locales/zh.ftl). Action palette labels use
`action-` IDs (for example `action-pane-split-right`). Keymap IDs remain
`pane.split_right`; translated palette entries retain them for searching.

## WASM SDK

```rust
use proteus_plugin::{host, i18n::{self, FluentArgs}};

fn example() -> Result<(), String> {
    let mut messages = i18n::catalog()?; // reads host::locale(), not WASI env
    messages.add_resource("en", r#"
files = { $count ->
    [one] { $count } file
   *[other] { $count } files
}
"#)?;
    messages.add_resource("zh", "files = { $count } 个文件")?;
    let mut args = FluentArgs::new();
    args.set("count", 3);
    host::notify(&messages.format("files", Some(&args))?, false);
    Ok(())
}
```

Use `include_str!("../locales/en.ftl")` to embed resource files. Keep the catalog
in plugin state. On `Event::ConfigChanged`, call `i18n::sync(&mut messages)`,
refresh localized action labels/status, and redraw. Re-register actions with the
same stable IDs to update their labels. Catalogs are private to each plugin;
reading `host::locale()` requires no permission. See the pane-list example and
its `locales` directory for initialization and reload handling.

`Catalog::format` returns `Result<String, String>` so plugins can handle missing
messages/arguments explicitly. Native UI convenience calls fall back to the ID
on errors; built-in resource coverage is tested.

The previous message-table registration API and `{name}` placeholder syntax have
been removed. Use `.ftl` resources, Fluent IDs, and `{ $name }` placeables.
