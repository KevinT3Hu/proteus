# 06 — AI (first-party plugins `proteus.ai` + providers)

## Goals

- Useful AI that understands panes, blocks, files and images as one context.
- Strictly optional: one switch, asked on first run (D8), zero footprint when off.
- Privacy by default: user always sees what is sent; secrets redacted; local models first-class.
- Agent mode deferred to v2 (D9).

## The switch

- `ai.enabled = true | false | nil` in `init.lua`. `nil` (default) means "not decided".
- First run with `nil`: a one-time non-modal card in the first window:
  "Enable AI features? Choose a local model (Ollama/llama.cpp) or a provider. You can change this any time." → [Set up] [Not now] [Never]. Choice persisted to state (`init.lua` setting always wins).
- Off means: AI plugins not loaded, no network, no keybindings, no palette entries, no UI hints.
- Build-time: cargo feature `ai` (default on). With `--no-default-features` the AI plugins are not embedded at all.

## Architecture

- `proteus.ai` (WASM): features, UI, context assembly, redaction, history.
- Provider plugins (WASM), each implementing a WIT `provider` interface (`list_models`, `chat_stream`, `count_tokens?`):
  - `proteus.ai-openai` — any OpenAI-compatible endpoint (OpenAI, OpenRouter, DeepSeek, vLLM, LM Studio...)
  - `proteus.ai-anthropic`
  - `proteus.ai-ollama` — also covers llama.cpp server via OpenAI-compatible mode
- Third parties can add providers. Network permission per provider is limited to its configured host.
- API keys in Secret Service keyring via the `secrets` permission; never in `init.lua`.
- Model choice per feature (e.g. small fast model for commands, larger for chat).

## Features (v1)

### 1. Command from natural language

- At a prompt (OSC 133 state), press `Ctrl+g a` (or `Alt+Enter`, configurable) → inline input overlay above the prompt.
- Type intent ("find big files changed this week") → streaming suggestion shown with a one-line explanation.
- `Enter` inserts into the prompt (never runs), `Tab` cycles alternatives, `Esc` cancels.
- Context sent: shell, OS, cwd, last N commands from blocks (configurable, default 5 commands without output).
- Commands flagged dangerous (`rm -rf`, `dd`, `mkfs`, `chmod -R`, `curl | sh`, `git push --force`...) shown with a warning style.

### 2. Explain / fix failed command

- When a block exits non-zero, gutter mark shows a small "?" (only when AI enabled; can be disabled).
- `Ctrl+g ?` or click → float with explanation and suggested fix; `Enter` inserts the fix into the prompt.
- Context: command, exit code, last 200 lines of output (redacted), cwd, shell.

### 3. Chat panel

- Sidebar or float surface; conversations per window, history stored locally (optional, off by default).
- Context is always explicit, shown as chips in a context bar above the input:
  - current block, selected text, a pane's visible screen / full scrollback, files (from file manager or `@path` completion), images (from file manager or screen).
- Each chip shows token estimate; total and per-request cost shown when the provider reports pricing.
- Assistant code blocks have actions: insert into prompt, copy, open in `$EDITOR`. No auto-execution.
- Images sent only to models that declare vision support.

## Privacy & safety

- Nothing is sent without a user action (keypress or click). No background analysis.
- Redaction pipeline before every request (local, in plugin):
  - known key/token patterns (AWS, GCP, GitHub, OpenAI, Anthropic, Slack, JWT, private key blocks),
  - `KEY=value` lines from `.env`-like content,
  - user-defined regexes in config.
  - Redacted spans replaced with `[REDACTED:<kind>]`; preview of the final payload available ("Show what will be sent").
- Input typed while the PTY is in no-echo mode (password prompts, detected via termios) is never recorded in blocks or context.
- Private panes: toggle per pane (`Ctrl+g p P`); excluded from AI and from `read-screen` for all plugins; indicated in the pane border.
- Optional local audit log of every payload sent (`ai.audit_log = true`), in `$XDG_STATE_HOME/proteus/ai-audit/`.
- Budget: optional monthly token or cost cap per provider; warning at 80%, block at 100%.

## v2: Agent mode (not in v1)

- Multi-step tasks; every proposed command shown with run / edit / skip.
- Optional auto-approve for read-only commands from an allowlist.
- Execution in a dedicated pane, optionally sandboxed with landlock (filesystem) and no-network.
